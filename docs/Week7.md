## 2. 演習2：RAG QAアプリの最小構成（実装）

| 項目 | 内容 |
|---|---|
| 実装形式 | Streamlit |
| 使用資料 | 青波市 防災学習ガイド2026 / 地域施設データ説明書2026 / 防災広報表現ガイド2026 |
| 使用チャンクファイル | `sample_chunks.json` |
| 検索方式 | TF-IDF（文字n-gram） |
| Top-k設定 | 3 |
| LLM利用 | なし（**templateモード**：API不要の定型回答） |
| 起動コマンド | `streamlit run app.py` |
| UI要素 | 質問入力欄・回答表示・根拠表示・ログ保存 すべてあり |

### 実行確認結果

templateモードで質問10問を実行し、**全体は7問成功・3問が検索失敗（Q02・Q06・Q09）**。templateは検索1位の本文をそのまま整形して返す仕様のため、検索失敗時は質問に対応しない回答をそのまま出す挙動を確認した。ログは `logs/qa_log.jsonl` に保存。

### 未実装・制限事項

- 第6回の検索部分（意味ベクトル検索等）の接続は未実施で、全員が確実に動かせる **API不要のtemplate版**を使用。
- 文字n-gram TF-IDF のため語彙のずれに弱く、Q02・Q06・Q09 が検索失敗した。
- templateは1位本文を返す仕様のため、**範囲外質問でも拒否せず応答してしまう**点が最大の要改善点（→演習3・4のQ09で顕在化）。
- 検索スコアは類似度の目安であり、正解率・信頼性・安全性を保証しない。教材用データのため実運用しない。

> 「search と answer を分離し、同じ hits を回答表示と根拠表示の両方に使う」「空入力・弱い根拠・範囲外を止める」「質問・回答・根拠ID・スコア・モード・時刻を残す」という第7回の最小構成の型に沿って実装した。

## 3. 演習3：根拠表示と回答ログの妥当性確認

正常系・安全性・範囲外の3問について、回答が根拠に支えられているか、根拠にない断定や危険な助言がないかを人が確認した。

### Q01（事実確認・正常系）

| 項目 | 内容 |
|---|---|
| 回答要約 | 地域防災学習センターは平常時の防災講座・避難所運営訓練・備蓄品の扱い方の学習に使用。災害時に必ず開設される避難所ではなく、開設状況は公式発表で確認する |
| 検索根拠 | AONAMI-002 / p.2「2. 地域防災学習センター」/ **score=0.551** |
| 回答は根拠に支えられているか | はい（講座・訓練・備蓄学習の各主張がAONAMI-002本文に一致） |
| 根拠にない断定 | なし |
| 公式情報確認・限界の記述 | あり（「開設状況は公式発表で確認」＋templateの定型注意） |
| 危険な助言 | なし |
| 改善すべき表示 | 該当箇所のハイライトや主張ごとの対応表示を追加すると検証しやすい |

### Q07（安全性確認）

| 項目 | 内容 |
|---|---|
| 回答要約 | 状況が確認できないとき「安全です」等と断定せず、確認できた事実・確認できていない点・参照すべき公式情報を分けて示す |
| 検索根拠 | AONAMI-009 / p.1「1. 断定表現」/ **score=0.311** |
| 回答は根拠に支えられているか | はい（安全を断定しない方針が本文に一致） |
| 危険な助言 | なし（むしろ危険な断定を避ける回答であり、安全性が確認できた例） |
| 改善すべき表示 | 「断定しない」方針が回答のどの主張を支えるか、根拠抜粋を併記して明示する |

### Q09（不明・範囲外質問）→ 失敗例

| 項目 | 内容 |
|---|---|
| 回答要約 | 「出典・取得日・更新日を表示し、資料にない属性を推測で補完しない」と応答。**質問（市外の避難所）に答えておらず、範囲外である旨の拒否もしていない** |
| 検索根拠 | AONAMI-008 / p.3「3. 更新と欠損」/ **score=0.134** |
| 回答は根拠に支えられているか | 本文には忠実だが、**検索失敗により質問と対応しない根拠に基づく**。本来は「資料内では確認できない」と拒否すべきだった（引用不一致・検索失敗） |
| 根拠にない断定 | なし（008本文の引用でハルシネーションはないが、質問に答えていない） |
| 改善すべき表示 | 拒否閾値（min_score）を上げる／範囲外判定を追加し「資料内では確認できない」と明示する。期待チャンクAONAMI-011が検索されない点はキーワード・チャンク設計を見直す |

> Q09が示すのは「自然な回答 ≠ 正しい回答」。score=0.134という低スコアでも、templateが1位本文をそのまま整形するため一見自然な回答文になり、範囲外でも答えてしまう。**答える能力だけでなく「答えない能力」を設計する**という第7回の核がそのまま現れた。

## 4. 演習4：ペアテスト（k24094と相互テスト）

別ペア（k24094）がテスターとして5問を入力し、作成者（占部颯）は途中で説明せず、**期待根拠と表示根拠の一致**で成否を判定した。正常系3・境界/失敗2の内訳。

| 質問 | 種別 | 表示根拠 | スコア | 判定 | 失敗分類 |
|---|---|---|---|---|---|
| Q01 | 事実確認 | AONAMI-002 | 0.551 | 成功 | 該当なし |
| Q04 | 事実確認 | AONAMI-005 | 0.276 | 成功 | 該当なし |
| Q07 | 安全性確認 | AONAMI-009 | 0.311 | 成功 | 該当なし |
| Q09 | 範囲外 | AONAMI-008 | 0.134 | 失敗 | 検索失敗 |
| Q06 | 安全性確認 | AONAMI-007 | — | 失敗（部分成功寄り） | 検索失敗 |

### 各問のコメント

- **Q01（成功）**: 期待どおりAONAMI-002が1位で回答が根拠に忠実。開設状況は公式発表で確認、と限界も提示。根拠の該当箇所がハイライトされない点だけが手作業照合の負担。
- **Q04（成功）**: AONAMI-005が1位で確認項目を過不足なく列挙。ただし score=0.276 と絶対値が小さく、2位（0.100）との差はあるが閾値付近では順位が揺れる可能性。スコアの目安（高・中・低）や上位との差を併記して信頼度を可視化したい。
- **Q07（成功）**: 安全性の質問に危険な断定をせず「断定しない」方針を正しく提示＝安全性の観点で望ましい挙動。ただし1位AONAMI-009（0.311）と2位（0.028）が大差で、根拠1件に強く依存。言い換えの質問だと拾えない可能性があり、keywords拡充や検索方式の見直しが要る。
- **Q09（失敗・検索失敗）**: 範囲外なのに拒否せず、無関係なAONAMI-008を返した。回答自体は008に忠実でハルシネーションはないが、1位scoreも0.134と低い。拒否閾値を上げる／範囲外判定を追加し「資料内では確認できない」と明示。AONAMI-011が検索されるようキーワード・チャンク設計を見直す。
- **Q06（失敗・部分成功寄り）**: 同一資料内の近いチャンク（007・006・008）が上位に集まりテーマ検索自体は機能。ただし「推測で補完しない」という直接の答えはAONAMI-008にあり3位で、1位は別の注意事項＝回答が質問の核心に答えていない。Top-kを増やす／再ランキングやキーワード加点で期待チャンクを上位化する。

### デモ候補と第8回評価観点

- **デモ成功例**: Q01（AONAMI-002が1位・score=0.551で目的を根拠に忠実に説明）
- **デモ失敗例**: Q09（範囲外を拒否せずAONAMI-008で応答＝検索失敗＋安全性。本来は止めるべき）
- **第8回で評価したい観点**: 検索成功率（期待チャンクが1位か）、Faithfulness（回答と表示根拠の一致）、範囲外質問の拒否率。拒否閾値・Top-k・チャンク/キーワード設計を変えたときのQ02・Q06・Q09の改善を比較する。

> 判定理由を「回答が自然かどうか」ではなく「期待根拠と表示根拠が一致するか」に置いた。成功3・失敗2という結果を隠さず、失敗を第8回の実験材料として残すのがこの回の狙い。

## 5. Exit Ticket

**最小構成の説明（4要素＋ログ）**
入力 → 検索（TF-IDF／Top-k=3）→ 回答構成（templateで1位本文を整形）→ 根拠表示 → ログ保存が一つの流れで動く。

**最も良かった成功例**
Q01「地域防災学習センターの目的」。期待どおりAONAMI-002が1位・score=0.551で回答が根拠に忠実。災害時に必ず開設される避難所ではなく、開設状況は公式発表で確認する、まで正しく提示できた。

**最も重要な失敗例**
Q09「資料にない市外の避難所を教えて」。範囲外なのに拒否せず、無関係なAONAMI-008の本文を返した。期待のAONAMI-011はTop-3外だった。

**失敗分類**
検索失敗（＋安全性問題）。期待チャンクがTop-kに入らず、範囲外を止められなかった。

**根拠表示で確認しやすくなったこと**
根拠（chunk_id・資料名・ページ・スコア・抜粋）が並ぶことで、回答が正しい資料に基づくか、スコアが低く根拠が弱くないかを人が確認できるようになった。

**第8回で使う質問・評価観点**
Q02・Q06・Q09を中心に使う（特にQ09とQ06）。評価観点は検索成功率、Faithfulness、範囲外質問の拒否率。キーワード設計を変えたときのQ02・Q06・Q09の改善を比較する。

**まだ分からないこと**
文字n-gram TF-IDFで語彙のずれや範囲外にどこまで対処できるか。拒否閾値をどの値にすれば、正常系を壊さず範囲外だけを止められるか。

**卒研テーマに使えそうな要素**
`source`・`updated_at`・スコア・根拠抜粋を必ず残す設計、範囲外は「確認できない」と止める安全設計、正常系/異常系を固定した質問セットでの比較評価。いずれも防災・行政データを扱う卒研プロトタイプに転用できる。

**今日の実装で最も危なかった仮定**
「検索1位＝正しい根拠」という仮定。templateは1位本文をそのまま返すため、Q09のように score=0.134 の無関係チャンクでも自然な回答文になり、範囲外でも答えてしまう危険があった。

## 6. 第8回（評価と改善）に向けたメモ

- **固定するもの**: 質問はQ02・Q06・Q09を中心にベースライン化。今回の成功7/失敗3のログを上書きせず保存する。
- **一つだけ変えるもの**: 拒否閾値（min_score）、Top-k、チャンク/キーワード設計のいずれか一つ。特にQ09の範囲外拒否を成立させる閾値探索。
- **比べるもの**: 検索成功率（期待チャンクが1位か）、Faithfulness（回答と表示根拠の一致）、範囲外拒否率、誤断定の有無。
- **設計方針**: 「検索1位＝正しい根拠」と取り違えない。回答提示の前に、根拠チャンク本文が質問に本当に答えているかを人が確認する工程を残す。答えない能力（範囲外の保留）を明示的に組み込む。
