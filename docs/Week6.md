### サンプルチャンク本文（doc01_A_001）

冒頭の見出し・注意書き・メタ情報欄（発行主体：青葉市危機管理課／文書種別：市民向け地域防災計画抜粋・RAG演習用／発行日 2026-06-01／更新日 2026-07-01／利用条件：授業内利用可・実災害対応には利用不可）に続き、「1. 災害時の情報確認」の本文（市公式サイト・公式SNS・防災情報メール・緊急速報メール・地域防災無線・避難所掲示を組み合わせて確認し、平常時から家族で二つ以上の確認手段を決めておく）までが1チャンク目に入った。

### メタデータ項目（チャンクに付与）

```
chunk_id=doc01_A_001, source=サンプル文書_青葉市地域防災計画抜粋_教材用（架空）,
publisher=青葉市危機管理課（架空）, issued_at=2026-06-01, updated_at=2026-07-01,
retrieved_at=07-17, heading=1.災害時の情報確認,
license_note=授業内利用可・実災害対応には利用不可, start_char=0, end_char=399
```

### 固定長分割で気づいた点

| 観点 | 内容 |
|---|---|
| 長すぎると感じた点 | 特になし |
| 短すぎると感じた点 | 第2節の「浸水した道路には進入せず、指定外の場所に駐車しない」のような禁止事項の列挙が境目で分断されやすい。第8節のメタデータ項目の列挙も途中で切れた。 |
| 根拠提示に向いている点 | 事実を問う質問に対し、余計な話題が混ざらずピンポイントで回答できる。 |
| 根拠提示に向いていない点 | 回答が分断されるため、「○○だが〜の時はこうする」という条件つきの内容だと後半が次チャンクに行き、一つの問いに対して複数の根拠をまとめて用意できない。 |

### 条件A/Bの比較コメント

- 条件A：焦点は合いノイズが少ない。しかし文脈が欠如したり、例外・条件つきの回答を用意できない。
- 条件B：目的の回答以外のノイズが混じり、クリティカルな回答を得にくい。ただし多角的な視点からの回答は得られる。

**次に試したい分割方法**: 段落ごとの分割。区切りのついた分割で一貫性のある内容になるか、クリティカルな検索ができそうかを試したい。

### Q1「停電や通信障害が長引く場合は何から情報を得るか」の検索結果

| 順位 | チャンクID | スコア | 出典/見出し | 関連度判定 |
|---|---|---|---|---|

### 検索で困った点

情報を得る「方法」ではなく、情報の堅牢性について言及した文章が検索にかかった。望ましくない結果だが、「情報」に関する見出しであるため関連度の判定が難しいと感じた（誤判定が起きやすい）。

### 改善案

文章の見出しをあらかじめ分類分けしておき、質問がまずどの大枠の見出しに当たるのかを判別してから検索したほうがよいと考えた。

## 5. Exit Ticket

**RAGを自分の言葉で説明**
チャット型AIがウェブ検索でインターネット上から情報を探すのと対照的に、ユーザが用意したデータセットをもとにAIが検索をかけ、その中から情報を取り出す仕組み。

**外部知識と根拠提示が必要な理由**
モデル内部の知識だけでは最新情報が入手できない。特に災害情報はリアルタイム性が必要なため、RAGと外部知識が必要。

**チャンク分割で難しかった点**
分割する量によって短くも長くもでき、それぞれにメリット・デメリットがあるため、用途ごとに切り替える必要がある。分割方法によっても結果が変わる。

**チャンクサイズで検索結果が変わる理由**
情報量が多いほど目的情報の検索精度が落ち、少ないほど取りこぼし（最適な情報を提供できないこと）が起きる。AIは確率で回答を引き出すため、材料が多いほど正解が埋もれやすい。

**埋め込み/ベクトル検索で分かったこと**
今回は埋め込みモデルを使わず、ローカルのTF-IDFで検索した。TF-IDFは単語や文字の表面的な一致で類似度を測る方式で、APIキーもネットワークも不要で全員が確実に動かせる利点がある。

**妥当性確認で見つけた問題**
スコアが高いチャンクが必ずしも質問の答えではなかった。Q2ではスコアが3問中もっとも高いチャンクが1位になったのに、本文は資料の出典確認の話で質問の答えではなかった。スコアだけを見ていたら誤った根拠を採用していた。本文を読んで初めて、関連度と根拠としての十分性が判定できると実感した。返ってきたチャンクは答えではなく根拠候補にすぎない。

**検索失敗分類と具体例**
三種類の失敗を観察した。

1. **文脈不足** … Q1（持ち物）で、持ち物リストがチャンク境界で分断され、1位には食料・懐中電灯しか入らず、飲料水・常備薬・書類が別チャンクに残った。
2. **検索漏れ** … Q2で、正しい記述を含むチャンクが1位に来ず、「確認」という共通語に引っ張られて無関係なチャンクが上位化した。
3. **ノイズ過多** … 全文が1チャンクになる条件Bでは、どの質問でも文脈は揃うが、質問と無関係な記述も一緒に返った。

**出典・更新日・引用が重要な理由**
古い資料を根拠に断定すると危険につながる。発行主体・発行日・更新日・取得日を必ず記録し、いつ・どの版を根拠にしたかを示せるようにする。チャンクIDや見出しを残しておけば、回答のどの部分がどの資料のどこから来たのかを後から示せる。防災という分野では、自然な説明よりも先に「根拠を示せること」が求められる。

**第7回で注意したい点**
RAGを使ったQAアプリを作るときは、スコアの高さを信頼度と取り違えない。回答を提示する前に、根拠チャンクの本文が質問に本当に答えているかを人が確認する仕組みを入れる。
